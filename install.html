Install

Drafted with AI, not yet reviewed

keycap consists of two Emacs packages, keycap and rhai-ts-mode, and keycap-server, a program keycap starts for each script. With Nix, all three come as one package; without Nix, Emacs installs the packages and cargo builds the server.

Requirements

  • Emacs 30.1 or later, built with tree-sitter (most distributions’ builds are).
  • Linux on x86-64 or AArch64, since fidget compiles shapes to machine code for these. macOS should work too without Nix, as fidget supports it, but I haven’t tested it.
  • Optionally, a GPU with Vulkan; without one, rendering uses all CPU cores instead.
  • Without Nix: git, a C compiler, Rust 1.95 or later, and the Liberation Sans font, which text() draws in unless a script names another. For the GPU, the server also needs the Vulkan loader, libvulkan.so.1.

Try it with Nix

To run keycap without changing your configuration, build an Emacs with it and run that: 

git clone https://tangled.org/rei.gay/keycap
nix-build keycap/default.nix -A emacs
./result/bin/emacs keycap/examples/knob.keycap

The first build compiles the server, which takes a few minutes. The knob’s script opens in keycap-mode, and C-c C-c renders it beside the script.

With Nix

The package builds the server, the grammar and the manual, and points keycap at them. Nix can fetch keycap itself, so no checkout is needed: 

let
  keycap = builtins.fetchTarball "https://tangled.org/rei.gay/keycap/archive/main.tar.gz";
in
(pkgs.emacsPackagesFor pkgs.emacs).emacsWithPackages (epkgs: [
  (epkgs.callPackage "${keycap}/package.nix" { })
])

With home-manager, the same callPackage goes in programs.emacs.extraPackages. main.tar.gz follows the main branch; to pin a commit, fetch <commit>.tar.gz with its sha256, or add keycap with npins or as a flake input with flake = false. From a checkout, the package is epkgs.callPackage ./keycap/package.nix { }.

The first build compiles the server, which takes a few minutes; it is built with keycap’s own nixpkgs, whatever yours is. rhai-ts-mode comes with the package, and .keycap and .fidget files open in keycap-mode. Errors are marked by Flymake, so turn it on for them: 

(add-hook 'keycap-mode-hook #'flymake-mode)

To check it, save knob.keycap, open it and press C-c C-c: the knob appears beside the script. M-x keycap-version names keycap’s version and the server’s, which are the same.

Without Nix

The Emacs packages

Evaluate these once, in *scratch* or with M-:, rhai-ts-mode first, since keycap needs it: 

(package-vc-install "https://tangled.org/rei.gay/rhai-ts-mode" nil 'Git)
(package-vc-install "https://tangled.org/rei.gay/keycap" nil 'Git)

Emacs can’t tell from a tangled URL that the repository is git, hence 'Git. Errors are marked by Flymake, so turn it on for them in your init file: 

(add-hook 'keycap-mode-hook #'flymake-mode)

Or, with use-package, put this in your init file instead, and the next start installs both: 

(use-package rhai-ts-mode
  :vc (:url "https://tangled.org/rei.gay/rhai-ts-mode" :rev :newest))

(use-package keycap
  :vc (:url "https://tangled.org/rei.gay/keycap" :rev :newest)
  :hook (keycap-mode . flymake-mode))

Without :rev :newest, use-package installs the commit that last changed the package’s version, which is the first one. Either way, each package is a git checkout in ~/.emacs.d/elpa/ (or ~/.config/emacs/elpa/, if your configuration lives there), and .keycap and .fidget files open in keycap-mode.

The server

Build it from the keycap checkout: 

cargo install --locked --path ~/.emacs.d/elpa/keycap/server

This takes a few minutes and puts keycap-server in ~/.cargo/bin; --locked keeps the dependencies at the versions keycap was tested with. The build stays in the checkout’s server/target, almost 1 GB, which makes the next one quick.

An Emacs started from a desktop launcher may not have ~/.cargo/bin on exec-path, where keycap looks for the server; naming it works however Emacs starts: 

(setq keycap-server-program "~/.cargo/bin/keycap-server")

The grammar

M-x rhai-ts-mode-install-grammar fetches tree-sitter-rhai and builds it with your C compiler, into ~/.emacs.d/tree-sitter/. From the next start, .rhai files open in rhai-ts-mode.

This is the upstream grammar; the patched one in rhai-ts-mode’s grammar/ is built by the Nix package only. Upstream marks floats written as 3. and nested block comments as errors, and misreads 0b and 0o numbers without one: 0b101 is 0 followed by b101.

Checking it

Open ~/.emacs.d/elpa/keycap/examples/knob.keycap and press C-c C-c: the knob appears beside the script. M-x keycap-version names keycap’s version and the server’s, which are the same unless one was updated without the other.

The manual

With Nix, the manual is in Info: M-x keycap-guide, or keycap in C-h i. Without Nix, M-x keycap-guide opens doc/keycap.org, which has no reference chapters, as they are written from the server’s documentation when the Nix package is built; the whole manual is on this site. C-c C-d on a name shows its documentation either way.

Nothing needs configuring; the user options are in the manual’s Customization, and how .keycap and .fidget scripts differ is in Dialects.

Troubleshooting

No keycap-server found: install keycap-server (…), or set ‘keycap-server-program’
Emacs didn’t find the server on exec-path; set keycap-server-program to its full path, as in The server.
Cannot activate tree-sitter, because language grammar for rhai is unavailable
The grammar isn’t installed; run M-x rhai-ts-mode-install-grammar.
requires rustc 1.95, from cargo
The Rust toolchain is too old; rustup update updates it.
text: no default font; Liberation Sans is not installed, so give a font
Install Liberation Sans, or name a font in the text call.
The preview’s header line says CPU and (no GPU)
The server found no Vulkan device: without Nix, check that the Vulkan loader and your GPU’s Vulkan driver are installed. On NixOS, a server built with cargo finds no loader unless LD_LIBRARY_PATH has vulkan-loader’s lib directory; installed with Nix, it needs nothing. The manual’s Preview problems has the other reasons the CPU renders.

Updating

  • With Nix, rebuild: main.tar.gz is fetched again once Nix’s copy is an hour old (tarball-ttl), and a pinned commit moves when you change it.
  • Without Nix, M-x package-vc-upgrade-all, then the same cargo install again, so that the server matches the package.

Uninstalling

  • With Nix, remove the package from the list and rebuild.

  • Without Nix, M-x package-delete keycap, then rhai-ts-mode; keycap’s checkout takes the server’s build with it. Then remove the server and the grammar: 

    cargo uninstall keycap-server
rm ~/.emacs.d/tree-sitter/libtree-sitter-rhai.so
