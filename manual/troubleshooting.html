When a script fails

An error stops the script where it happens:

  • Flymake underlines the token that caused it, marks its line in the fringe and counts it in the mode line; with point on the token, the echo area shows the message.
  • The preview’s header line shows the line number and the message, and a click on it goes to the line.
  • The preview keeps the last model that worked, so it doesn’t go blank while a line is half typed.

Example: misspell screw_hole in the plate from the Quick start.

The mark is on the innermost place it can be: an error inside a function is marked on its line in the function, and the message names the calls that led there. An error in an imported file or in the prelude is marked at the call that reached it, or at the import, its message starting with the file and line. M-x flymake-goto-next-error goes to the next mark, and M-x flymake-show-buffer-diagnostics lists them all. Error messages has the messages a script most often meets.

Warnings and notes leave the script running. Warnings mark a draw whose shape pokes out of the script’s bounds, a script that draws nothing, shapes that are empty everywhere, and, without bounds, a shape unbounded on every axis, such as a bare gyroid. In a .keycap file, notes mark a call of a fidget built-in that has a better keycap call, such as rectangle where rect is exact, and say why. A line that reads // keycap: no-prefer, anywhere in the file, silences them, for a script that keeps fidget’s calls on purpose.

Error messages

cannot compare Tree types during function tracing
A comparison (<, == and the rest) with a tree; see Choices without if.
Variable not found: w
Inside a fn, a variable of the script’s; declare it const and read it as global::w, or pass it in. In a module, an exported constant is also read as global::NAME.
Function not found: grow (Tree, i64)
A function called with arguments of types it has no definition for: a typo, a wrong argument count, or a script function called as a method (see Methods and chaining). difference (Tree, Tree, Tree) means three arguments where two go.
Syntax error: Expecting ';' to terminate this statement
A missing ; at the end of the line before.
Runtime error: field center must be provided for RotateX
A transform called with a map needs every field; leave the map out to get the defaults.
Runtime error: field xy is not present in Circle
A misspelt field; completion inside the map lists the right ones.
Runtime error: missing argument of type Vec<Tree>
union or intersection of a single shape.
Runtime error: missing argument of type Tree
An array of shapes where a transform wants one; wrap it in union.
Runtime error: shape does not have an argument of type Tree
A tree where a shape wants a number: integer math such as sin(1) or sqrt(4) made one; see Numbers and trees.
Runtime error: shape does not have an argument of type Vec3
An argument the shape has no field for, here a 3D point for a 2D shape.
Data type incorrect: Vec3 (expecting Vec2)
A vector of the wrong size for a field.
the script ran more than 20000000 operations; is a loop endless?
A loop that does not end, or one far too large.
bounds are already set
A second bounds call.
bounds are empty on x: lower must be below upper
The corners of bounds swapped.
import cycle: a.rhai -> b.rhai -> a.rhai
Files importing each other.
text: no installed font is "JetBrains Mono:bold"
No installed family of that name; fc-list : family lists them. A font file needs a / or its .ttf or .otf in the name to be taken as one.
svg: cannot read plate.svg: No such file or directory
The path is relative to the script, or to Emacs’s directory for a buffer without a file.

Surprises without an error

  • 5 / 2 is 2, and sqrt(4) is a tree; see Numbers and trees.
  • circle(1, 2) is a circle of radius 2: two positional numbers fill the same field.
  • cylinder(r, h) takes the radius first.
  • Prelude shapes are centred on the origin, along Z too; #{anchor: "bottom"} or a height of [0, h] stands them on z = 0.
  • An offset of fidget’s box or rectangle keeps sharp corners: their fields are bounds; use cuboid and rect.
  • After scale or scale_uniform, offsets come out the wrong size; use scale_exact.
  • reflect(s, "xy") mirrors across Y (fidget a386417); use reflect_z.
  • revolve_y does not revolve (fidget a386417); use revolve.
  • fidget’s mix is a hash, not an interpolation; use lerp.
  • A repeat whose shape is off-centre cuts the copies at the cell’s edges; move the result instead.
  • draw in an imported module draws too.

Preview problems

The model is tiny or far away
The fitted bounds are loose or unbounded on an axis; set bounds, or press b to compare with the script’s.
The header line says the shapes’ intervals are NaN
Interval arithmetic evaluates a field over a whole box at once, and its intervals are NaN for a division by an interval that holds 0, and for sqrt, acos or ln of one that reaches out of their domain, even where the values never do. 2 * x * y / (x * x + y * y) lies within ±1, but its interval over a box does not, so sqrt(1 - 0.9 * square(...)) of it is NaN there. A NaN interval proves nothing, and min and max pass it on, so the fitted bounds come out loose or missing, and renders evaluate every voxel, which is slow on the CPU and too slow for the GPU. Clamp such a value to the range it has anyway (clamp(v, -1.0, 1.0)), take sqrt of max(v, 0.0), keep a divisor that is positive away from 0 (max(d, 1e-6)), or set bounds.
A shape is cut off
It pokes out of the script’s bounds; Flymake warns at its draw.
The preview is slow
See Performance; the header line shows the render time and backend.
The header line says CPU and a reason
The GPU was asked for, or was the sooner, and the CPU rendered instead: there is no GPU, a shape needs more registers than the GPU has, the shapes are too slow for the GPU even in small tiles, or the GPU failed on this scene (its device was lost, or it hung), which keeps the scene on the CPU until the script is evaluated again. Shapes are too slow for the GPU when interval arithmetic tells nothing about them, so that every voxel is evaluated; see Bounds.
Nothing is drawn
The script ran, but drew nothing, or drew empty space (a difference that removed everything, an intersection of disjoint shapes); the sdf view shows where the field is negative. The header line says nothing in view when no pixel shows a shape, and nothing on this slice in the 2D views.
